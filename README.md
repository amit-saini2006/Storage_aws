# ☁️ CloudVault — Cloud-Based Personal File Storage System Using AWS S3

A modern web application that allows users to upload, view, download, and delete personal files stored in Amazon S3.

Built as a college project demonstrating cloud computing concepts with **React + Vite** (frontend), **Python Flask** (backend), and **Amazon S3** (storage).

> **Note:** This is a single-user deployment suitable for a college demonstration. It does not include multi-user authentication. See [Limitations](#limitations) for details.

## System Architecture

```
┌──────────────┐        HTTP/REST         ┌──────────────┐       AWS SDK (Boto3)      ┌──────────────┐
│              │  ───────────────────────▶ │              │  ──────────────────────▶  │              │
│   Browser    │      GET/POST/DELETE      │  Flask API   │      Upload / List /      │  Amazon S3   │
│  (React +    │  ◀─────────────────────── │  (Python)    │  ◀──────────────────────  │   Bucket     │
│   Vite)      │        JSON + URLs        │              │    Download / Delete      │              │
└──────────────┘                           └──────────────┘                           └──────────────┘
     Port 3000                                Port 5000                             AWS Region (ap-south-1)
```

### How it works

1. The **React frontend** runs in the browser and makes API calls to the Flask backend.
2. The **Flask backend** receives requests, validates inputs, and communicates with Amazon S3 using Boto3.
3. **Amazon S3** stores the actual files. Files are never exposed publicly — access is controlled through time-limited **presigned URLs**.
4. In **development mode** (`DEV_MODE=true`), the backend uses local filesystem storage instead of S3, so the app works without AWS credentials.

### AWS Services Explained

- **Amazon S3 (Simple Storage Service):** Object storage service for storing any amount of data. Files are stored as "objects" in "buckets." We use S3 to store user-uploaded files securely.
- **Amazon EC2 (Elastic Compute Cloud):** Virtual servers in the cloud. We deploy our Flask + React application on an EC2 instance.
- **IAM (Identity and Access Management):** Controls who can access AWS services. We create a least-privilege IAM policy that only allows S3 operations on our specific bucket.
- **Presigned URLs:** Temporary, secure URLs generated by the backend that allow the browser to download files directly from S3 without making the bucket public.

## Local Development Setup

### 1. Clone the repository

```bash
git clone <repository-url>
cd cloud-file-storage
```

### 2. Backend setup

```bash
cd backend

# Create a virtual environment (recommended)
python -m venv venv

# Activate it
# Windows:
venv\Scripts\activate
# macOS/Linux:
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Create .env from template
copy .env.example .env          # Windows
# cp .env.example .env          # macOS/Linux
```

The default `.env` has `DEV_MODE=true`, which uses local filesystem storage. No AWS credentials needed.

### 3. Start the backend

```bash
python app.py
```

The API server starts at **http://localhost:5000**.

### 4. Frontend setup (new terminal)

```bash
cd frontend

# Install dependencies
npm install

# Start the dev server
npm run dev
```

The frontend starts at **http://localhost:3000** and proxies `/api/*` requests to Flask.

### 5. Open the application

Visit **http://localhost:3000** in your browser. You should see the CloudVault dashboard.

## AWS Configuration

To use real Amazon S3 storage instead of local files:

### Step 1: Create an S3 Bucket

1. Log in to the [AWS Console](https://console.aws.amazon.com/).
2. Go to **S3** → **Create Bucket**.
3. Bucket name: `your-unique-bucket-name` (must be globally unique).
4. Region: Choose your nearest region (e.g., `ap-south-1` for Mumbai).
5. **Block all public access:** ✅ Keep enabled (important for security).
6. Click **Create Bucket**.

### Step 2: Create an IAM User with Least-Privilege Policy

1. Go to **IAM** → **Policies** → **Create Policy**.
2. Use this JSON policy (replace `your-bucket-name`):

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "CloudVaultS3Access",
            "Effect": "Allow",
            "Action": [
                "s3:PutObject",
                "s3:GetObject",
                "s3:DeleteObject",
                "s3:ListBucket",
                "s3:HeadObject"
            ],
            "Resource": [
                "arn:aws:s3:::your-bucket-name",
                "arn:aws:s3:::your-bucket-name/*"
            ]
        }
    ]
}
```

3. Name it `CloudVault-S3-Policy`.
4. Go to **IAM** → **Users** → **Create User**.
5. Name: `cloudvault-app`.
6. Attach the `CloudVault-S3-Policy`.
7. Go to **Security Credentials** → **Create Access Key** → **Application running outside AWS**.
8. Save the **Access Key ID** and **Secret Access Key** securely.

### Step 3: Update `.env`

```env
AWS_ACCESS_KEY_ID=AKIA...your-key
AWS_SECRET_ACCESS_KEY=your-secret-key
AWS_REGION=ap-south-1
S3_BUCKET_NAME=your-bucket-name

DEV_MODE=false
```

### Step 4: Restart the backend

```bash
python app.py
```

You should see: `☁  Running in PRODUCTION mode (Amazon S3 storage)`

## EC2 Deployment Guide

### Step 1: Launch an EC2 Instance

1. Go to **EC2** → **Launch Instance**.
2. Name: `CloudVault-Server`.
3. AMI: **Amazon Linux 2023** or **Ubuntu 22.04**.
4. Instance type: **t2.micro** (Free Tier eligible).
5. Key pair: Create or select an existing one.
6. Security Group — allow:
   - **SSH** (port 22) from your IP only.
   - **HTTP** (port 80) from anywhere (0.0.0.0/0).
   - **Custom TCP** (port 5000) from anywhere (for testing).

### Step 2: Connect to EC2

```bash
ssh -i your-key.pem ec2-user@<public-ip>
```

### Step 3: Install dependencies

```bash
# Amazon Linux
sudo yum update -y
sudo yum install -y python3 python3-pip nodejs npm git

# Ubuntu
sudo apt update && sudo apt upgrade -y
sudo apt install -y python3 python3-pip python3-venv nodejs npm git
```

### Step 4: Clone and set up

```bash
git clone <repository-url>
cd cloud-file-storage

# Backend
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# Configure .env with your AWS credentials
nano .env

# Frontend
cd ../frontend
npm install
npm run build
```

### Step 5: Serve the built frontend from Flask

For a simple deployment, copy the frontend build into the Flask static directory or use Nginx.

### Step 6: Run with Gunicorn

```bash
cd backend
gunicorn -w 4 -b 0.0.0.0:5000 app:app
```

### Step 7 (Recommended): Use IAM Roles instead of credentials

When running on EC2, create an **IAM Role** with the S3 policy and attach it to the EC2 instance. Then remove `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` from `.env` — Boto3 automatically uses the instance role.

### Step 8: Set up Nginx (Optional, for port 80)

```bash
sudo yum install -y nginx   # or sudo apt install nginx

sudo tee /etc/nginx/conf.d/cloudvault.conf << 'EOF'
server {
    listen 80;
    server_name _;

    location / {
        root /home/ec2-user/cloud-file-storage/frontend/dist;
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        client_max_body_size 50M;
    }
}
EOF

sudo systemctl restart nginx
```

## Troubleshooting

| Issue                                  | Solution                                         |
|----------------------------------------|--------------------------------------------------|
| "Unable to connect to the server"      | Ensure Flask is running on port 5000             |
| "NoSuchBucket" error                   | Check `S3_BUCKET_NAME` in `.env`                 |
| "InvalidAccessKeyId"                   | Verify AWS credentials in `.env`                 |
| "AccessDenied" on S3                   | Check IAM policy covers the correct bucket       |
| Upload fails silently                  | Check browser console + Flask terminal for errors|
| CORS errors                            | Use the Vite proxy (dev) or Nginx (production)   |
| Large file upload timeout              | Increase `MAX_FILE_SIZE_MB` and Nginx `client_max_body_size` |
| "File type not allowed"               | Check `ALLOWED_EXTENSIONS` in s3_service.py      |

## Limitations

- **Single-user system.** There is no authentication. Anyone with access to the URL can see and manage all files. This is intentional for a college-project demonstration.
- **No encryption at rest** beyond S3's default server-side encryption.
- **No file versioning** — deleting a file is permanent.
- **50 MB default file-size limit** — configurable via `MAX_FILE_SIZE_MB`.
- **Dev mode uses local disk** — not suitable for production.

## Cleanup

To avoid unexpected AWS charges:

1. **Delete all objects** in your S3 bucket, then **delete the bucket**.
2. **Terminate the EC2 instance** if you launched one.
3. **Delete the IAM user** and policy created for this project.
4. Check the **AWS Billing Dashboard** to confirm no resources are running.

## Demonstration Guide

### For presenting to a teacher:

1. **Start the app** with `DEV_MODE=true` (works without AWS).
2. **Show the Dashboard** — explain the stats cards and layout.
3. **Upload a file** — demonstrate drag-and-drop and the progress bar.
4. **Browse files** — switch between table and grid views, use search.
5. **Preview an image** — click the preview button on an uploaded image.
6. **Download a file** — show the presigned URL concept (or direct serve in dev mode).
7. **Delete a file** — show the confirmation dialog.
8. **Show the code** — explain the React → Flask → S3 flow.
9. **Show the tests** — run `pytest -v` and walk through the test cases.
10. **(Optional)** Switch to `DEV_MODE=false` with real AWS credentials and repeat the demo to show actual S3 integration.

### Key talking points:

- "Files are stored in Amazon S3, not on the server. This means storage is virtually unlimited and highly durable (99.999999999% durability)."
- "We use presigned URLs so the S3 bucket stays private. The browser never talks to S3 directly — the Flask server generates temporary access URLs."
- "The IAM policy follows least-privilege — it only allows the 5 specific S3 actions needed, and only on our bucket."
- "In development mode, we swap the S3 backend for a local filesystem mock, so students can run the app without an AWS account."
